## 3. Token cost (H1)

| N (subset, mode) | Alexandria (median) | Native (median) | Ratio native/alx |
|------------------|---------------------|-----------------|------------------|
| 20 (close, hybrid) | 3805.0 | 1496.0 | ~0.39× |
| 20 (close, fts) [baseline] | 1821.0 | 1332.5 | ~0.73× |

- Mean: alexandria 3583.4, native 2180.9. IQR alexandria [200.0–5197.5], native [954.0–2934.0].
- **Measured fact:** Under hybrid, Alexandria's median context cost (3805) is *higher* than native
  (1496) and roughly double its own FTS-baseline cost (1821). Hybrid's higher recall means the model
  more often finds and *fetches* a skill body (the token-expensive step), whereas FTS more often
  returned nothing and cost only the resolve round-trip. The token picture is a consequence of
  retrieval succeeding more, not of hybrid being intrinsically heavier per query.

## 4. Retrieval latency (H2)

| N | Cond | median | cold median | warm median |
|----|------|--------|-------------|-------------|
| 20 | alexandria | 69.3 ms (mean 77.6) | 70.1 ms | 69.3 ms |
| 20 | native     | 1.16 ms (mean 1.31) | 1.20 ms | 1.14 ms |

- **Measured fact:** ~69 ms hybrid round-trip (FTS + vector search + RRF fusion) vs ~1.2 ms local
  lookup; immaterial vs an LLM turn, and in line with the ~47–82 ms FTS round-trips seen elsewhere —
  adding the vector leg did not materially change retrieval latency at N=20.

## 5. Accuracy (H3)

| N | Cond | Model-choice (rate [CI]) | Recall@5 (rate [CI]) | Consult compliance |
|----|------|--------------------------|----------------------|--------------------|
| 20 | alexandria (hybrid) | 0.650 [0.517–0.767] (39/60) | **1.000 [1.0–1.0]** (43/43) | 0.717 (43/60) |
| 20 | native | 0.717 [0.600–0.833] (43/60) | n/a | 0.833 (50/60) |
| 20 | alexandria (fts) [baseline] | 0.733 [0.617–0.833] (44/60) | 0.957 (44/46) | 0.767 (46/60) |

- **Conditional recall@5 = 1.000 (43/43):** every time the model consulted, hybrid retrieval surfaced
  the gold skill in the top 5 — up from 0.957 under FTS on the same subset. On a semantically-dense
  (near-variant) library this is exactly where the semantic leg is expected to help: the RRF fusion
  recovered the gold skill in the handful of cases lexical FTS ranked just outside the top 5.
- **Model-choice 0.650 vs native 0.717:** CIs overlap heavily — a statistical tie, as in the FTS
  baseline (0.733 vs 0.733). Alexandria's model-choice sits a touch below its own FTS baseline here
  purely from a lower consult rate this run (0.717 vs 0.767); conditioned on consulting, retrieval was
  flawless.
- **Measured fact:** Hybrid lifts conditional retrieval recall to a perfect 1.000 on close-semantics
  (vs 0.957 FTS), while model-choice remains a native/Alexandria tie within noise. The residual
  Alexandria model-choice gap is consult-compliance, not retrieval quality.

## 6. Interpretation

- **H1 (token): not supported on close-semantics under hybrid — and inverted.** Native's median is
  lower (1496 vs 3805). Higher recall drives more skill *fetches*, which is where tokens are spent;
  the FTS baseline looked cheaper for Alexandria mainly because it retrieved (and so fetched) less.
  This is a retrieval-quality/token trade-off, not a hybrid overhead.
- **H2 (latency): supported direction, immaterial magnitude.** The vector leg + RRF added no
  meaningful latency at N=20 (~69 ms).
- **H3 (accuracy): hybrid delivers perfect conditional recall; model-choice is a tie.** The headline
  win is recall@5 1.000 vs FTS 0.957 — the semantic leg closes FTS's residual near-variant misses on
  a dense library. Model-choice stays tied with native within CIs, limited by consult compliance.

## 8. Threats to validity

- nrep=3 reduces but does not eliminate consult-compliance noise; Alexandria's model-choice this run
  is consult-rate limited (0.717), not retrieval limited (recall@5 was perfect).
- **Local embedding provider** (`local-hashing-ngram-v1`, a deterministic hashing/n-gram embedder),
  not a production sentence model. It is sufficient to recover near-variant gold skills on this dense
  20-skill subset, but recall gains on harder/sparser corpora may differ with a stronger embedder
  (swap in via the HTTP provider, no code change).
- Native accuracy/token modeled, not scraped (conservative for H1).
- Tokenizer proxy; single machine/model/client/subset; N=20 only.
