## 2. Headline — the largest catalog margin of the three subsets

| Metric | catalog (backend) | native | Δ |
|--------|------------------:|-------:|--:|
| **Model-choice accuracy** | **0.967 [0.917–1.0]** | 0.700 [0.583–0.817] | **+0.267** |
| Consult compliance | 0.967 | 0.817 | +0.150 |
| Token cost (median) | 1781 | 1273 | +40% |

- Catalog model-choice **0.967** vs native **0.700** — the widest gap seen (+0.267), fully
  non-overlapping CIs. On a corpus of *near-duplicate* skills, native's resident-but-skipped behavior
  cost it twice: it consulted less (0.817) AND, when it did, the full-description preload did not make
  it pick more accurately than the catalog's compact lines. Catalog both consulted more (0.967) and
  selected correctly almost every time.
- Token premium ~40% here (smaller absolute bodies on this subset make the per-line id+name overhead a
  larger fraction), still a modest absolute cost (1781 vs 1273 median).

## 3. Interpretation — all three 20-skill subsets now agree (real backend)

| Subset (backend) | catalog | native | Δ |
|------------------|--------:|-------:|--:|
| random-20 (`run-20261009-132631`) | 0.833 | 0.700 | +0.133 |
| sparse-20 (`run-20261009-142645`) | 0.983 | 0.833 | +0.150 |
| **close-20 (this run)** | **0.967** | **0.700** | **+0.267** |

The catalog beats native on model-choice on **every** 20-skill subset against the real
`alexandria://catalog` resource, by +0.13 to +0.27, every CI pair non-overlapping or nearly so. The
margin is largest exactly where selection is hardest (close/near-duplicate), which is the governed
registry's best case: a compact, resident, ACL-scoped catalog gets the agent to engage and pick
correctly where native's heavier preload does not. The cost is a consistent token premium (25–40%),
linear in N like native — the catalog is an accuracy+governance win, not a token optimization.
