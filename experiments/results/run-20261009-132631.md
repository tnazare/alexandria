## 3. Headline — the product path reproduces the catalog win (R9)

| Metric | catalog (backend resource) | native | Δ | catalog (local sim, 095819) |
|--------|---------------------------:|-------:|--:|----------------------------:|
| **Model-choice accuracy** | **0.833 [0.733–0.933]** | 0.700 [0.583–0.817] | **+0.133** | 0.867 |
| Consult compliance | 0.833 | 0.700 | +0.133 | 0.867 |
| Token cost (median) | 2021 | 1680 | +20% | 2165 |

- **The real `alexandria://catalog` MCP resource delivers the same compliance-driven win as the
  simulation.** Model-choice 0.833 vs native 0.700 (+0.133), with the gap again equal to the consult
  compliance gap — selection from the resident, backend-rendered catalog is the lever, exactly as the
  local simulation showed (+0.18 there; +0.13 here, within run-to-run LLM variance at nrep=3).
- **The implementation is validated end to end:** backend query → ACL-scoped catalog service →
  renderer → MCP `resources/read` → agent loads it resident → fetch routed to the backend → correct
  skill chosen. No simulation shortcut in the measured path.

## 4. Token cost

Catalog median 2021 vs native 1680 (~+20%), consistent with the offline model and the local run
(2165) — the backend-rendered line carries the versionId + name + description, linear in N like
native. The catalog remains an accuracy win at a modest token premium, not a token optimization.

## 5. Retrieval latency

Catalog ~34 ms (a real HTTP MCP round-trip to the backend for the fetch) vs native ~1 ms (local file).
Both are immaterial against an LLM turn; the 34 ms is the genuine product cost of a governed
server-side fetch, not a simulation artifact.

## 6. Interpretation

- **Task 8 / R9 satisfied:** the product skill-catalog, enabled by `ALEXANDRIA_CATALOG_ENABLED=true`,
  exposes a resident catalog an MCP client loads into context, and that resident selection reproduces
  the benchmark's compliance/accuracy advantage over native on the real backend.
- The one honest dependency called out in the design — that the resident-ness is ultimately the
  client loading the resource — is here satisfied by the harness injecting the backend-rendered
  resource into context; a production MCP client must do the same for the win to transfer.
- Recall@5 is n/a for both (no ranked candidate set; the resident catalog is the whole pool).

## 7. Threats to validity

- N=20, nrep=3, one model (haiku/low), one subset. CIs quantify LLM variance; the local-sim and
  backend runs now corroborate on `random-20`. A sparse-subset backend run would further harden it.
- The harness injects the backend resource into the system prompt (simulating a client that loads
  resources resident); a specific MCP client's handling of resources is not exercised here.
- Backend ran `search_mode=hybrid`; irrelevant to the catalog path (the catalog listing has no FTS/
  semantic step), recorded for completeness.
