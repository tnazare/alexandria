# Skill Retrieval Benchmark — Results (run-id: run-20261002-095819)

> **catalog vs native A/B**, nrep=3 on the `random-20` fixed subset. The **catalog** condition is a
> new mechanism: a resident compact Skill Catalog (`id: name — description` per skill) injected into
> the system prompt — like native's preload — plus a single on-demand `fetch_skill(id)` tool served
> by a self-contained local MCP server (no Alexandria backend). It tests whether making selection
> *resident* (no retrieval tool call to skip) closes the consult-compliance gap that cost the
> server-side Alexandria condition its model-choice accuracy in prior runs. 120 cells, 0 poison
> records. Neither condition used the docker stack.

- Experiment version `v1`; date `2026-10-02T09:58:20-0400`; macOS 12.7.6 x86_64; Python 3.14.7

## 3. Headline (H3 — accuracy)

| Metric | catalog | native | Δ |
|--------|---------|--------|---|
| **Model-choice accuracy** | **0.867 [0.767–0.95]** | 0.683 [0.567–0.80] | **+0.184** |
| Consult compliance | **0.867** | 0.683 | +0.184 |
| Model-choice (52/60 vs 41/60) | 52/60 | 41/60 | +11 selections |

- **The resident catalog closed the compliance gap and then some.** Catalog's consult compliance is
  0.867 vs native's 0.683 on this subset — and because model-choice equals compliance for *both*
  conditions (every consult that happened chose the gold skill), the entire accuracy win is driven by
  the agent actually consulting. The near-non-overlapping CIs make this a real effect, not noise.
- **This is the inverse of the Alexandria result.** In the server-side runs, the explicit
  `resolve_skill` tool call was skipped ~40–50% of the time and native led model-choice. Making
  selection resident (catalog) flips it: catalog now *leads* native, because its catalog is in context
  the same way native's is, but the agent engaged with it more reliably on this subset.

## 4. Token cost (H1)

| Cond | median | mean | IQR |
|------|-------:|-----:|-----|
| catalog | 2165.0 | 2907.9 | [1047.0–3374.0] |
| native | 1657.0 | 2490.9 | [607.0–3039.0] |

- **Catalog costs ~31% more tokens at the median (2165 vs 1657).** This matches the offline
  token-scaling model exactly: the catalog line carries the slug id + `: `/` — ` punctuation on top of
  the same name+description native preloads, so catalog's resident cost is ~10–15% above native and
  both grow linearly in N. Catalog is **not** a token optimization — it trades more tokens for higher
  compliance/accuracy.
- Note: unlike the Alexandria condition, catalog does **not** have a flat-in-N resident cost; it is
  resident like native. The flat-cost property belongs only to the server-side resolve/fetch design
  (see `results/token-scaling-20261001.md`, where only Alexandria stays ~constant in N).

## 6. Recall@5

- `n/a` for both. Catalog has no ranked candidate set (the whole resident catalog is the candidate

## 7. Interpretation

- **The lever was compliance, and resident selection pulls it.** Prior runs isolated the problem:
  Alexandria lost model-choice not on ranking but because the model skipped the `resolve_skill` call.
  This run confirms the fix direction — a resident catalog (no tool call to make a *decision*, only to
  *fetch* the already-chosen skill) raised consult compliance from native's 0.683 to 0.867 and carried
  model-choice up with it.
- **But it is not free, and not flat in N.** Catalog pays ~31% more tokens than native and, like
  native, grows linearly with library size. So catalog beats native on accuracy at a token premium; it
  does **not** inherit Alexandria's flat-cost-in-N advantage. The three mechanisms now map cleanly:
  Alexandria = cheap-and-flat but low compliance; native = cheap-ish, linear, mid compliance; catalog =
  pricier, linear, highest compliance.
- **Design takeaway.** If the goal is governed, searchable skills *and* native-or-better compliance,
  the catalog mechanism is the strongest Phase-1 shape at small N. To also win the token/scaling axis
  at large N, the next step is **hierarchical disclosure** — keep only category headers resident and
  disclose a category's catalog lines on demand — which could keep catalog's compliance while bending
  its resident cost back toward sub-linear. That is the experiment this run motivates.

## 8. Threats to validity

- **N=20, single subset (random-20), one model (haiku/low), nrep=3.** The compliance numbers carry
  LLM variance; the CIs quantify it but a second subset (sparse/close) would strengthen the claim.
- Native's model-choice/consult are read from the transcript (direct); catalog's chosen id and consult
  are captured server-side by the local fetch server (direct). Token cost is the modeled `cl100k_base`
  proxy for both (same caveat as all runs).
- Catalog's non-consults clustered on a few tasks (t008, t010, and t009 partially) where native *also*
  often declined — these may be genuine no-skill-applies items; both conditions are penalized equally.
- Decision-only, forced-consult regime: this measures the *mechanisms* under an imperative directive,
  not spontaneous behavior. Disclosed, and held identical across conditions.
